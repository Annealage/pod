# Progress report - Annealage Pod

**Date**: 2026-04-29
**Phase**: 3 partial (firmware-level smoke complete, on-target SWD validation pending)

## 1. What this project is

mpy-pod is a hardware-in-the-loop test rig for MicroPython, built as a single ESP32-S3 replacement for Octoprobe's existing two-RP2040 Annealage Pod. The S3 takes the DUT plugged in as a USB host, exports it to a remote PC via USB/IP, multiplexes a synthetic CMSIS-DAP-v2 debug probe onto the same USB/IP server (so stock pyOCD / OpenOCD / probe-rs see a normal local probe), forwards a DUT UART over a separate TCP socket, runs MicroPython for power/relay/GPIO orchestration, and offers an I2C / SPI slave personality so DUT-as-master code can be tested. Wi-Fi only on rev1; an ESP32-P4 + Ethernet + PoE variant is documented as a sibling target if Wi-Fi reliability proves insufficient under POD load.

Source spec: `docs/esp32-s3/spec.md`. Architecture: `docs/esp32-s3/architecture.md`. Phase plan: `plan/`.

### 2.2 Firmware

The firmware is a MicroPython esp32-port build with five custom C user modules, one C user-module-style helper that wraps an internal C backend, and a frozen `annealage_pod` Python package.

**Board variant** `src/boards/ESP32_S3_ANNEALAGE_POD/`:
- USB-CDC and USB-Serial-JTAG disabled at the mpconfigboard level so the USB-OTG controller is free for host mode.
- Octal PSRAM enabled.
- Custom partition table: `factory 2M` + `ota_0 4M` + `ota_1 4M` + `vfs` (remainder).
- Bootloader rollback enabled, ESP_TASK_WDT enabled at 30 s.
- Console on UART0 GPIO43/44 via the onboard CH340N USB-UART bridge.
- Pin map exposed as `machine.Pin.board.<NAME>` per Appendix A §A.5.1.

**C user modules** `src/c_modules/`:
- `usbip/`: USB/IP server on TCP/3240, multiplexes two virtual devices on one TCP listener. APP_CPU pinned. `virtual_device_t` ops table for the synthetic-probe registration. URB dispatch matrix per `research/usbip-multiplexing-design.md`. 21 host-portable unit tests.
- `usbhost/`: real backend on the IDF `usb_host` component (TinyUSB host is not bundled in IDF v5.5.1; same fallback as the existing `referencea/esp-usbip-bridge`). Two APP_CPU tasks; per-pipe binary semaphore signalling; composite CDC + MSC handled.
- `dapprobe/`: ARM-software CMSIS-DAP `DAP.c` and `SWO.c` vendored under `vendor/cmsis-dap/` with license headers preserved. Port glue in `port/` bridges the vendored macros to WS-D's `swd.h` / `swo.h`. Synthetic CMSIS-DAP-v2 USB device with `iInterface = "CMSIS-DAP"` (the load-bearing string for pyOCD and probe-rs recognition), EP1 Bulk-OUT for DAP commands, EP2 Bulk-IN for DAP responses, EP3 Bulk-IN for SWO trace, ZLP discipline on EP3 per probe-rs #448.
- `dapprobe/io/`: HAL-direct SPI2 + GDMA SWD I/O engine (bypasses `spi_master` per Phase 0.3 spike findings); SWDIO direction strobed via `dedic_gpio` between TX-only and RX-only sub-frames; UART1 + UHCI two-tier SWO ring (64 KB DRAM tier-1, 8 MB PSRAM tier-2) drained by an APP_CPU-pinned task.
- `uartbridge/`: TCP-to-UART forwarder on a configurable port (default 2000), per-session UART config, three-task pinned model, optional RFC2217-style baud renegotiation. 290 host-portable protocol assertions.
- `slaveio/`: hardware-driven I2C-slave (V2 driver on I2C1) and SPI-slave (SPI3) register-table responders with mutual exclusion. ISR fills/serves; async MP callbacks via `mp_sched_schedule`. 12 host-portable regtable tests.
- `ops_wdt/`: `esp_task_wdt` wrapper.
- `ops_log/`: `esp_log_set_vprintf` hook + TCP listener for fan-out logging.
- `ops_ota/`: written but **not built into rev1**. Its `esp_https_ota` and `esp_http_client` REQUIRES cannot reach the IDF main component because user-module includes are gated by `if(NOT CMAKE_BUILD_EARLY_EXPANSION)` in the MP esp32 port; appends arrive after `idf_component_register` has locked in REQUIRES from the discovery phase. Pure-MP fallback in `annealage_pod.ops.ota` ships instead.

**Frozen Python package** `src/mpy/annealage_pod/`:
- `power.py` with INA228 driver derived from TI SBOS882, clean room, supporting VTARGET (3v3) and DUT-USB (5V) rails with current/voltage telemetry plus `vbus_present()` via the INA228 voltage register.
- `relays.py` with relay 1..7 control: set/get/batch/pulse/all_off.
- `dut.py` with `reset(mode='swd'|'nrst'|'power'|'relay')`.
- `slave.py` thin wrappers over `slaveio` C API.
- `compat.py` RP_INFRA shim per Appendix B (3 module vars, 12 Pin objects, 4 helpers); fixes the upstream `get_relays` parameter-shadowing bug.
- `carrier.py` for I2C-EEPROM carrier identification.
- `supervisor.py` with hybrid-stateless cleanup hook (default: power-off both rails, open every relay).
- `boot.py` orchestration: load `/credentials.json`, bring up Wi-Fi, register mDNS, start usbip server, attach dapprobe, start uartbridge, bind REPL listener, mark OTA valid.
- `ops/{ota,wdt,log,time}.py` with C-shim-then-pure-MP fallback selection.

**Build and tooling** `src/tools/`:
- `setup-idf.sh`, `build.sh`, `flash.sh` (auto-detects single esp32 via mpy-dev, refuses if 0 or > 1 found), `monitor.sh`.
- `src/VERSIONS` pins ESP-IDF v5.5.1 and MicroPython v1.29.0-preview-69-g8a56be666.
- `.github/workflows/build.yml` builds in `espressif/idf:v5.5.1` container.

### 3.5 Headline result

**The architectural payload of the design is validated**: a single ESP32-S3 acting as USB host to a real MicroPython DUT, multiplexing a synthetic CMSIS-DAP-v2 device on the same USB/IP server, where stock pyOCD and stock probe-rs running on a remote Linux host both recognise the synthetic device as a normal CMSIS-DAP probe via the iInterface = "CMSIS-DAP" string match. The novel firmware piece (dual-busid USB/IP with a synthetic device alongside a real-host-forwarded device) is on the wire and being seen correctly by both kernel-side `vhci-hcd` and user-space probe libraries.

## 4. What is still unknown

### 4.1 Bulk URB completion path

`mpremote` against the forwarded Pico CDC and `pyocd reset` against the synthetic probe both hang after the initial enumeration. Both paths exercise USB-Bulk endpoints. Plausible causes:

- WS-A's `USBIP_RET_SUBMIT` for IN transfers may not be completing back to the host promptly. The handler is in `src/c_modules/usbip/usbip_server.c`.
- WS-C's dapprobe DAP-command interpreter may not be processing Bulk-OUT URBs and queuing Bulk-IN responses. Unit tests passed against host fixtures, not against a live IDF-side StreamBuffer.
- WS-B's usbhost may not be propagating IN-transfer completions back through to the multiplexer.

A debug pass with instrumented log lines per URB at each layer (host -> usbip server -> usbhost or dapprobe -> response -> usbip server -> host) would isolate the breaking link.

### 4.2 SWD-to-DUT actually drives the wires

The SWD pins (S3 GPIO10 SCLK, GPIO11 SWDIO) are wired to the Pico's SWD header. WS-D's HAL-direct SPI2 + GDMA backend is in place. WS-C's port glue maps the vendored CMSIS-DAP DAP_config macros to those swd_* calls. But neither has executed against a live target because the bulk URB path above blocks the test before SWD I/O is reached. Open until DAP_Info or DAP_Connect actually traverses the chain.

### 4.3 mDNS announce

`annealage_pod.boot.up()` reports `mdns: None` even when Wi-Fi is connected. Either the `mdns` ESP-IDF component import failed silently or the announce call returned without registering. Hostname-based discovery (`annealage_pod-<chipid>.local`) is the planned discovery mechanism for testbed_micropython integration; until this is fixed, deployments must use the raw IP.

### 4.4 TCP REPL listener has no accept loop

`boot.up()` calls `start_repl_socket()` which only `bind()`s and `listen()`s; no task is ever scheduled to run `repl_accept_one()`. Connections from the host hit kernel SYN-ACK then close (we observed FIN-WAIT-2). `mpremote connect tcp://...` fails because of this, plus an unrelated pyserial URL-scheme issue. Fix: spawn a `_thread`-based accept loop or wire it into asyncio inside `up()`. Until this is fixed, REPL access is UART0-only.

### 4.5 `usbip.attached_devices()` MP API returns `[]`

The MP-side accessor on the `usbip` C module returns an empty list even though both virtual devices are exported and host-side `usbip list -r` proves the registry is populated. Cosmetic; doesn't affect operation but breaks the introspection helper that some Phase 3 tests rely on.

### 4.6 OTA C shim deferred

`ops_ota` is written but excluded from the firmware build because the IDF main component's REQUIRES cannot pick up user-module additions in the MicroPython esp32 port's current build flow. Fully diagnosed in commit `affe3e4`. `annealage_pod.ops.ota.update(url, experimental_pure_mp=True)` is the rev1 path. Lift the restriction once an upstream MP hook lands or after a small board-cmake patch.

### 4.7 INA228 hardware not wired

Power telemetry is implemented (`annealage_pod.power.vtarget.current_mA()` etc.), but no INA228 is wired on the dev rig perfboard. Validation deferred to PCB rev1.

### 4.8 Slave-mode personalities not exercised

`slaveio` for I2C and SPI is implemented but Phase 3 hasn't connected a second MCU as I2C/SPI master. Code compiles and unit tests pass; on-target validation pending.

### 4.9 SWO trace pipeline not exercised

WS-D's UHCI tier-1 + PSRAM tier-2 SWO ring is in the firmware but no DUT is currently producing ITM trace. Validation deferred until a DUT firmware that emits SWO is loaded.

### 4.10 OTA round-trip

Pure-MP OTA path exists but no end-to-end OTA cycle has been run.

### 4.11 Phase 3 cleanup hook firing

P3.2 in the runbook checks that REPL TCP disconnect triggers the supervisor cleanup hook (DUT power off, relays open). Cannot be tested until §4.4 (REPL TCP accept loop) is fixed.

## 7. Recommended next moves

In order of leverage:

1. **R11 debug pass**: instrument the bulk URB path. One small change at each layer (usbip server, usbhost, dapprobe synthetic) emitting `ESP_LOGD` per submit / complete with busid + endpoint. Re-run `pyocd reset` and read off where the chain stops.
2. **R12 fix**: spawn an accept task in `annealage_pod.boot.up()` so TCP REPL is reachable. One-line `_thread.start_new_thread(repl_accept_loop, (listener,))`.
3. **mDNS fix**: log the actual IDF mdns return code from `annealage_pod.boot.mdns_announce`.
4. **First successful pyOCD operation against the Pico via the synthetic probe**: target is `pyocd commander -u 0123456789ab --target rp2040 -c 'reset halt; rr 0'`. This is the headline screenshot.
